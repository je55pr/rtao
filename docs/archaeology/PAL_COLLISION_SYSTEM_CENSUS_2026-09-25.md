# PAL collision-system census - 2026-09-25

This census separates RTAO's recovered static vehicle/world contact from collision
families that the browser had no native consumer for. The goal is not to make
everything solid. Unknown dispatch or enable semantics stay explicit and
fail-closed.

## Ordinary race dynamic vehicle path

PAL installs `0x00218888` as a separate task through `0x00204F88`; it is not a
branch of the per-car terrain frame `0x0021C920..0x0021D4EC`. The task walks the
fixed 24-slot car array at `0x01820470` with a `0x270` byte stride.

For each ascending unordered pair it:

1. requires `(car+0x198 & 0x7fff) != 0` on both cars;
2. obtains the fixed-position delta and 3D distance through `0x0021E1C0`;
3. rejects zero distance and distance `>= 1.8`;
4. calls oriented admission helper `0x00218470` in both directions;
5. if admitted, moves both `+0xA0` fixed positions symmetrically;
6. replaces both X/Z `+0xF0` velocities with their signed-int average;
7. invokes controlled-car event hook `0x002186D0` when either car has low
   `carFlags` bits set.

The admission helper tests four source points at car
`+0x140/+0x150/+0x160/+0x170` in the other car's inverse frame (`+0xB0`).
Those slots are now closed to their producer: the seven-probe contact loop at
`0x0021C280` writes transformed/query-adjusted probes consecutively from
`car+0x110`, so the pair task consumes probes 3–6. Their authored table entries
at `0x002A1E00..0x002A1E30` are the rectangle corners
`(-0.9,+1.5)`, `(+0.9,+1.5)`, `(-0.9,-1.5)`, `(+0.9,-1.5)` in local X/Z.
The frame preserves the resulting world-space four-lane snapshots after terrain
query/support adjustment. X must lie in `[-0.9,+0.9]`, Z in
`[-1.5,+1.5]`; Y is not an admission dimension.

The separation scalar is `(0.9-distance)/distance`; a negative result is replaced
with `0.01`. This means admitted pairs between 0.9 and 1.8 still receive the
retail minimum nudge rather than being left overlapped. The position conversion
uses PAL `CVT.W.S` with FCR31 cleared: nearest-even. The routine has no
pairwise yaw/spin impulse or damage write. AI-to-AI pairs use the same law.

The browser implementation is `nativeRaceVehicleCollision.ts`, scheduled after
per-car native frames by `OrdinaryRaceSession`. `NativeRaceFrameState` retains
the exact probe-3..6 snapshots generated by the contact stage; the dynamic pass
does not reconstruct them from renderer wheel geometry. It mutates only the
PAL-owned fixed position and velocity fields touched by the task; the same-frame
float coordinate snapshot remains unchanged. F3 reports admitted car-slot pairs.

## Controlled-car event hook boundary

`0x002186D0` computes relative X/Y/Z velocity through `0x0021E1C0`, multiplies
its magnitude by 1000, and has a normal branch that can issue impact kind 6 and
sound 20. It uses `car+0x210` as contact persistence/cooldown. In the normal
branch a controlled car can emit only when the scene `+0x28` bit `0x40` is
clear, the counterpart cooldown is zero, and controlled `carFlags & 0x0fb0`
is zero; the counterpart cooldown is then written as 8.

A second branch is selected from the callback-owner `+0x1c` state and writes
150/180-tick persistence while also touching additional owner/scene records.
That owner's ordinary-race value has not yet been witnessed. The physical
car-to-car law does not depend on this branch, so browser physics is enabled
while this presentation/event branch remains evidence-gated. No collision
damage or destruction semantics are invented.

## Browser substitutions that are deliberately not used here

The race pair path does not use the browser world triangle cache, render meshes,
arbitrary spheres, Three.js bounding boxes, host rigid-body impulses, or a
player-only collision callback. It is a separate fixed-point dynamic layer.
Likewise, recovering car-to-car contact does not change ordinary static terrain,
support, suspension, or authored obstacle queries.
